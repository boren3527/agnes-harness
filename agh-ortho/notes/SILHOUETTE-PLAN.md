# 剪影数值化 —— 把"像不像"的**轮廓**那一档变成机器可判（v0.1，2026-10-09）

> 目标：让"模型与照片的轮廓是否一致"从**人眼**升级为**可判定**，且**全程不让像素穿过 seam**
> （工具结果里出现图片块会 `E_STEP_FAILED` 并永久毒化会话 —— 这条约束是设计前提，不是待解决的障碍）。
>
> 不变的前提：**图片进模型只有两条路** —— ① 人把图**贴进对话**（可以，已验证）；② 平台 media 面（computer-use，
> 未验证）。**插件工具结果**永远不带图块。所以本方案**不依赖**"图进模型"，而是把图变成**数**。

---

## 1. 今天缺的两段

| 段 | 现状 | 缺什么 |
|---|---|---|
| 下游渲染 | `camera.add` 有，但**只有透视**（`lens`）；`capture` 渲的是**视口** | ① `camera.add` 支持 **正交**（`type: ORTHO` + `ortho_scale`）；② 一个"**用场景相机渲到文件**"的 op |
| 上游比较 | 我们已有 `outline`（每视图的 u/v 跨度，米）与 `photo_check`（人写区间） | 把**渲染出的剪影**量成**同一套数**，并与 `outline` 比 |

## 2. 下游请求（两条 op 改动，一位小数都不多）

1. `camera.add { …, type: "ORTHO"|"PERSP", ortho_scale: <number> }`
   —— 正交时必须能给出 `ortho_scale`（视口高度对应的世界尺寸），**它是像素↔米的唯一换算依据**。
2. `render.still { camera: <name>, width, height, path, transparent?: true }`
   —— 用**场景相机**渲到文件；返回 **path / sha256 / bytes / ortho_scale / width / height**
   （**绝不返回图片块**，与 `capture` 同样的纪律）。
   `transparent: true` 时胶片透明 ⇒ "剪影 = alpha>0"，提取最稳（不需要猜背景色）。

## 3. 数的形状（两侧**同一套字段**，否则不可比）

```json
{ "view": "front",
  "width": 512, "height": 512,
  "ortho_scale": 2.0,                    // 视口高度对应的世界尺寸（米）
  "covered_fraction": 0.081,             // 非背景像素占比
  "bbox_px": { "x0": 210, "y0": 40, "x1": 300, "y1": 470 },
  "touches_edges": { "left": false, "right": false, "top": false, "bottom": false },
  "aspect_m": 0.2 }                      // (x1-x0)/(y1-y0)，**单位无关**，是主要比对象
```

- **两条硬规则**：
  1. **换算必须来自 `ortho_scale` 与分辨率**（`米/像素 = ortho_scale / height`），**不许估**；
  2. **判据的精度不能超过渲染的精度**：容差 ≥ **2 像素折算成的米**（或相对 1%，取大者）。
     （渲染是采样，1 像素就是它的分辨极限 —— 这是那条老规矩的又一次现身。）
- **两条独立路径**（沿用 numeric 的做法）：下游自报这三个数**是声明**；我们**自己解 PNG** 复核
  （原型已存在：`.agnes/work/png-measure.mjs`，zlib 解 PNG + 反 filter，能算覆盖率/包围盒/是否贴边）。
  两者不符 ⇒ **blocking**（说明其中一侧的换算或渲染不对）。

## 4. 比较怎么落到现有机制上

```
照片  ──人读──▶ photo_check 区间（w_over_h_min/max）      ← 已有
模型  ──参数──▶ outline（每视图 u/v 跨度，米）             ← 已有
渲染  ──剪影──▶ aspect_m（米）                            ← 本方案新增
                 ↑ 与 outline 比（几何自洽），与 photo_check 比（像不像照片）
```

- **与 `outline` 比**：同一视图、同一坐标系 ⇒ 差值超容差即 **blocking**（说明"渲染出来的轮廓"与"参数算出来的轮廓"不一致，
  要么渲染错、要么参数错）。
- **与 `photo_check` 比**：把剪影的 `aspect_m` 也塞进同一区间比较 ⇒ **"像不像"第一次有了机器判据**，
  而不再只有"模型自己算的 outline"这一条自证。
- 形状的**审美/细节**（线条、五官、发型）**仍然只归人**：这不是本方案的目标，也不该硬塞进来。

## 5. 验收（四条，都可判定）

- **A1 分辨率无关**：同一场景渲 512 与 2048 两张 ⇒ 折算成**米**的 `aspect_m` 在容差内一致
  （证明像素↔米的换算对；若两张差得比 2 像素还多，就是换算错了）。
- **A2 与已知真值一致**：拿我们那个已知样本（0.4 × 0.4 × 2 m 的方块）渲前视图 ⇒
  `aspect_m` 必须等于参数侧 `outline` 的 0.200（±容差）—— **这条不通过，整条链就没有意义**。
- **A3 已知错误必须被抓**：把某个部件挪一下（或换一个不对称样本）⇒ 比较必须**报出不一致**
  （只报"一致"的判据等于没判据）。
- **A4 seam 零穿透**：`render.still` / `capture` 的返回里**只有** path/sha256/bytes/尺寸，
  **没有**图片块 —— 加一条断言锁住（会话毒化的代价太大，不能靠自觉）。

## 6. 明确不做

- 不做"把渲染图自动喂给模型"（会毒化会话；且平台 media 面只接受 computer-use 的产物）。
- 不做"靠模型看像素判形状"（像素进不了工具结果；模型只能读文本里的数）。
- 不做非正交渲染的比对（透视下"轮廓"随距离变化，与我们的正交视图**不是同一个量**）。
