# agh-ortho 闭环规程（v1）

这份文件写给**在这个工作区里工作的 agent（模型）**，以及在旁边看的人。
它把"照片 → 参数 → 验证 → 建模 → 交付"这个循环写成**可复现的步骤**，而不是靠口述。

设计依据：`CONTRACT.md`（参数化优先、三态、双档校验）、`SKELETON-STATUS.md`（实测结论）、
`DOWNSTREAM-REQUEST-readback.md`（下游缺口）。

---

## 0. 角色分工（先认清谁做什么）

| 步骤 | 谁做 | 为什么是它 |
|---|---|---|
| **① 看图 → 候选参数** | **模型** | 只有模型看得见**用户上传的照片**。工具看不见任何图像（上游契约 §2.3 实测：工具产出的图连模型也看不见）。所以**不要**试图让某个工具去"分析图片" —— 它只能编造观察。 |
| **② 自检（便宜）** | **`agh_ortho_fit`** | 纯计算、零依赖、不需要 Blender。挡掉绝大多数低阶错误。 |
| **③ 形态核对** | **`agh_ortho_fit` 替模型核对** | 模型看得见照片、看不见我们的图，所以它把**读到的比例写进 `photo_check`**，由 fit 与我们算出的 `outline` 比。**这是把照片纳进自动循环的唯一机制**，且不再依赖模型自觉。 |
| **③b 图纸复核（③ 的图形那半边）** | **人** | 六视图排在**一张图纸**上（`sheet.svg`）：排错了、比例尺不统一、体量个数不对，在这张图上一眼看得出，而分图永远看不出。**复核必须在 ④ 之前发生** —— ④ 是唯一贵的一步。图纸由一次便宜的 `agh_ortho_save` 落盘（不需要 Blender）。 |
| **④ 建模** | **`agh_blender_apply_ops`** | 真的写进场景。 |
| **⑤ 读回验证（贵）** | **`agh_ortho_fit` + `against_scene: true`** | 唯一能证明"下游真的照做了、尺寸也对"的检查。 |
| **⑥ 交付** | **`agh_ortho_save`** | 落成带 sha256 的产物包。 |
| **批准** | **人** | `apply_ops` / `save` / `stop` 声明为需要同意（若会话开着 YOLO 则静默执行 —— 要知道当前模式）。 |

## 1. 两段式：便宜的每轮跑，贵的只跑一次

```
①  模型看图 → 参数 v_n
②  fit（不带 against_scene）                        ← 每轮都跑，零成本
      verdict=revise → 按 revise_hints 改，回 ①
      verdict=fit    → 进 ③
③  fit：它写下的 photo_check vs 我们算出的 outline  ← 每轮都跑，零成本（**不再是靠自觉**）
      对不上 → 回 ①（要么几何错，要么读数错）
③b agh_ortho_save { 同一组参数, run_id: "<名字>-candidate" }   ← 便宜：不碰 Blender
      人打开 run 目录里的 sheet.svg（一张图纸：六视图 + 全图比例尺）
      不像照片 → 回 ①；像 → 才允许进 ④
④  agh_blender_start → agh_blender_apply_ops { ops: <fit 返回的 ops> }
⑤  fit { 同一组参数, against_scene: true }           ← 只跑一次，贵
      失败 → 先归因（见 §4），再决定改什么
⑥  agh_ortho_save { 同一组参数, run_id: "<名字>" } → agh_blender_stop { force: true }
```

**③b 与 ⑥ 必须是两个不同的 `run_id`。** `save` 按 `run_id` 幂等：如果候选那轮已经用了交付那个 id，
交付这轮的 `against_scene` 只会拿回旧描述符，**读回永远不会被记录**。工具会明确告诉你
`readback_not_recorded: true` —— 看见它就去换一个 `run_id`，不要当成成功。

**迭代的对象是参数，不是六视图。** 六视图是参数的投影；改参数才可能让视图变对，光看视图不会。

## 2. 每一轮该看 `fit` 的哪些字段

| 字段 | 怎么看 |
|---|---|
| `verdict` | `fit` 才允许进下一步。`revise` 时**不要**申请 apply_ops。 |
| `revise_summary.blocking` | > 0 必须处理；`warning` 可留但要自知 |
| `revise_hints[]` | **逐项逐轴**。每个 hint 的 `where` 就是该改的位置。**一轮只改被点名的那些**，别顺手动别的（否则无法归因是哪一步改好的）。 |
| `validation.checks[]` | 每条带自己的 `ok`。失败项就是具体的原因。 |
| `three_state` | `downstream_cannot`（只能删或在 `unresolved` 里声明）/ `emitter_not_yet`（等 lowering）/ `declared_by_author` / `needs_attention`（未知特征或未决形状 —— 要处理） |
| `numeric.residual_max` | 必须为 0。不为 0 时**看 §4**。 |
| `outline` | **③ 的输入**。逐视图、逐对象的 `u_m` / `v_m` 与 `w_over_h`。拿它和照片比比例、体量个数、大小排序。 |
| `sheet` | **③b 的指针**（不是图本身）：`convention`（第一/第三角法）、`shared_scale`、`cells`（每张视图落在图纸哪一格）、`review_before_apply_ops`（这张图能回答的四件事）。图纸正文**有意不重复**发在这里（同一份几何发两遍就是翻倍上下文）—— 要文件就 `save`，要文本就 `agh_ortho_views`。见 §3.10。 |
| `photo_check` | **③ 的判定**。它会拿你写在 `params.photo_check` 里的**区间**与 `outline` 算出的比例对一遍；落在区间外就是 **blocking**（区间相对半宽上限 30%，容差按你声明的小数位数推）。见 §3.5。 |
| `overlaps` | 两个物体几乎占同一空间时给出 warning（只在重叠超过较小那个的一半时才报，避免噪音） |
| `declared_relative_confidence` | 只用来**排序**（哪个尺寸最没把握）。见 §5。 |
| `anchor` | 没有它（且没声明 `proportions_only`）就是 blocking。见 §3。 |
| `ops` | `verdict=fit` 时，这就是要喂给 `agh_blender_apply_ops` 的东西，**原样传**。 |

## 3. 缺 `scale_anchor` 是**必须修**的，不是可选

单张照片只有一个投影方向，深度与遮挡天生有歧义。所以**绝对尺寸的唯一来源**是一个已知真实长度：

```json
"scale_anchor": { "pixel_len": 340, "real_len": 2.1, "ref": "door_height" }
```

- 门 ≈ 2.1 m、砖、人、A4 纸、足球门 —— 任何你**确实知道**长度且能在照片里量出像素数的东西。
- **脆弱性**：所有绝对尺寸都乘同一个比值。参照物认错、或 `pixel_len` 读偏 10%，**每一个尺寸都偏 10%**。
  这不是可以忽略的误差 —— 它意味着**整份模型等比例地错**。
- 如果只要比例、不要绝对尺寸：显式写 `"assumptions": ["proportions_only"]`。
  **不声明就当作缺锚点处理** —— 因为不声明的话，一批看起来很有信心的"米"其实没有依据。

## 3.5 `photo_check`：把"像不像照片"变成**可核对**的输出

参数里写一个 `photo_check`：把你**在照片里读到的比例**写成**区间**（不是点）。

```json
"photo_check": {
  "front": { "w_over_h_min": 0.55, "w_over_h_max": 0.68, "note": "极值在我读数里飘" },
  "top":   { "w_over_h_min": 1.4,  "w_over_h_max": 1.6 }
}
```

`fit` 拿**它自己算出来的** `outline.<view>.w_over_h` 与你的区间对：

| 情况 | 结果 |
|---|---|
| computed **落在区间内** | 通过 |
| computed **落在区间外** | **blocking**：两个数摆出来，要么几何错、要么读数错，**必须调和** |
| 区间**太宽**（相对半宽 > 30%） | **blocking**：这么宽的区间什么都通过，等于没读 |
| 整个字段省略 | 如实记成"未核对"，**不会被当成通过** |

### 为什么要区间、为什么是 30% —— 这两条都是**实测来的**

同一个模型对**同一张照片**两次读数给出 `w_over_h = 0.60` 与 `0.77`，**相差 28%**。由此确定：

1. **"一个数 + 一个猜的容差"是假严谨**。原先固定 ±25% 恰好落在它自己的噪声里 ——
   那次"13.4% 通过"其实什么都没证明。
2. **判定改成"落在申明的区间里"**，判定才是确定的。
3. **但区间必须有上限**，否则声明 ±100% 就什么都通过了 —— 那是新的同义反复。
   所以 30% 这个上限同时是"允许的诚实不确定性"与"不允许的蒙混"的分界。

### ⚠️ 这一档**做不到**什么（必须一起说出去）

**它只能抓量级性的错误（比如差 2 倍），certify 不了 10% 级别的一致** ——
眼睛读一个线稿轮廓根本支持不了那个精度。`fit` 的载荷里也是这么写的，不要在前面加戏。

### 两条禁令

- **不要照抄算出来的数字**（也不要为了通过而把区间放宽）：那会让这个检查变成**同义反复**，
  等于**没有读照片**。建议里的原话是 "either turns this check into a tautology"。
- **留空的正确写法是"整个键省略"**，不要写 `{"w_over_h_min": null}` ——
  null 不是数字，schema 会直接拒掉那一次调用（实测被拒过一次）。

## 3.6 `revise_hints` 的用法，以及一条**实测踩过**的坑

`revise_hints` 的 `where` 就是该改的位置，**一轮只改被点名的那些** —— 否则无法归因是哪一步改好的。

⚠️ **坑：一条"指错原因"的 hint，比没有 hint 更糟。**

实测发生过：一条指令说"`head` 太宽，**这就是整体偏宽的原因**，把 head 收窄"。
但实际包络是 `ball`(−0.327) 与 `fist_R`(0.377) 撑出来的，`head` 只有 0.6 —— **收窄 head 对整体宽度的
影响是 0**。于是循环变成：收窄 head → 量 → 没变 → 再收窄 → 还是没变……**一个永远达不到的定点**，
模型会一直转下去。

**规则：**
1. 下修改指令**之前**，先确认因果真的成立。最省事的做法是**先问一个只读的问题**
   （"谁的极值决定了这个量？"），拿到答案再决定改谁。
2. 一条 hint 必须指向**可满足的**修改。如果做完它而指标不动，那这条 hint 就是错的。
3. 排查这类死循环时先看**审计日志**：如果工具调用停了、但会话还在输出，那是**模型侧文本跑飞**，
   不是工具在循环 —— 磁盘上不会有任何副作用。
4. 打断：TUI 里 **`Ctrl-C` 按一次 = 取消当前这一轮**（1 秒内连按两次 = 取消并退出）。

## 3.7 一条通则：**判据的精度不能超过输入的精度**

这条已经**实测咬了两次**，所以单列出来：

| 第几次 | 判据 | 输入的真实精度 | 后果 |
|---|---|---|---|
| 1 | numeric：「残差必须**恰好**为 0」 | 两条独立算术路径的往返噪声 ~**1e-16** | 20 个对象产生 34 条 blocking，**整条闭环堵死** |
| 2 | photo_check：拿 `0.780736` 去比边界 `0.78` | 模型写的是**两位小数**（±0.005 的写法误差） | 只超 **0.09%** 却被判成和"差 2 倍"一样的 blocking |

**做法**：先问"这个输入能支持多少位"，再定判据的容差。

- numeric：噪声 ~1e-16、真实误差 ≥1e-6 ⇒ 容差取 **1e-9**（空档中间）
- photo_check：按**申明的写法精度**给容差（写 `0.78` ⇒ ±0.005），封顶在中点的 2%
- 两处都**始终报出实际数值与容差**，并且把"不含容差的严格判定"也一并给出 ——
  擦边通过必须**看得见**，不能被容差悄悄吃掉

**判据比输入更精确，产出的不是严谨，是假严谨。**

## 3.8 两条**实测踩过**的硬规矩

### ① 已落盘的 run 是**只读**的：要改，先复制到 run 目录之外

实测发生过：一轮拿到新指令后，把 **`photo-round-1b/parameters.json` 就地改了**（它是那个已交付 run 里的产物，
它的 sha256 就记在同一个包的 `report.json` 里）⇒ **那个包当场自相矛盾**。

- **没有守卫拦这个**：`save` 会拒绝写进别人的 run 目录（`E_RUN_NOT_OWNED`），但文件工具直接改是拦不住的
- **而且回退不了**：同一份内容换个键序就是另一个 sha256。实测：同长度 8752 B 的副本，字节不同 ⇒ **无法精确还原**
- **正确做法**：`cp` 到 run 目录之外（例如 `.agnes/work/<round>/parameters.json`），改副本，再走 `fit`/`save`

### ② 两种 sha256 格式共存，别混

| 出处 | 格式 |
|---|---|
| 产物描述符的 `sha256`（`report.json` 里） | **64 位裸十六进制**，**不带**前缀 |
| harness 的包 integrity | **带 `sha256-` 前缀** |

实测：我自己的核验脚本就混了这两者，于是 9 个产物**全部**报成"不符"（而它们其实都对）。
**核验脚本必须先看清自己要读的是哪一种。**

## 3.9 三条**跨路对齐**的约定（都不挡路，但请照做）

两条都来自"参数化"与"生成网格"两条路要对齐这件事，而且**都不需要真去跑那些生成项目** —— 是设计层的。

### ① `part`：每个部件声明它**是什么**

StdGEN 那类项目的核心贡献不是网格，是**语义分解**（身体/衣服/头发分开）。而我们的 `assembly`
本来就是**带名字的部件** —— 两边撞到了同一个答案，但名字不同。**共享分类**才能让两条路在部件级比对。

共享词汇表（写在工具里）：`body` · `clothing` · `hair` · `prop` · `structure` · `furniture` · `ground`

```json
{ "id": "shirt", "feature": "box", "part": "clothing", ... }
```

- **缺了只 warning、不挡路**（已有模型不带它，照常工作）—— 但报告里会列出来
- **用了表外的名字也 warning**：一个不共享的名字**没法跨路对齐**
- ⚠️ **`part` 说的是"是什么"；"怎么做的"（参数化 / 生成的网格）是另一个轴**，记在描述符的 provenance 里。
  **两个轴不能混**（历史上混过一次 `acquisition` / `provenance`，教训在 notes §9.9）

### ④ 规范摆放：**底面贴 z=0、水平居中**

借的是 CharacterGen "规范化"的思路，但用在另一半上 —— 它统一的是**姿势**，我们统一的是**摆放**。

- **理由**：不居中的话，两次迭代的 diff 会把**整体位移**混进每一个对象的坐标，看 diff 全是噪音
  （实测：`photo-round-2` 的水平包络是 x[-0.33, 0.38]，并没有居中）
- `fit` 的 `placement` 段报出包络、`base_z`、水平中心、以及**相对容差**；偏离就给 warning
- **这是"便于比较"的约定，不是几何正确性** —— 只报不挡

### ③ 交付的 `parameters.json` 是**规范键序**

与 ④ 同一个理由（"两轮 diff 只看数值"），只是这一条管的是**文件的字节**：

- 顶层按 `INTENT_KEYS`、`assembly` 项按**声明顺序**（`id → feature → 尺寸 → 位置 → 分类 → 来源`）、
  其余对象按键名排序；数组顺序不动
- 实测教训（2026-10-09）：同一组参数两次 `save`，**取值逐项相同、字节不同** —— 因为键序跟着
  调用方写的那个对象走（`id,feature,w,d,h,at` vs `at,d,feature,h,id,w`）。于是
  "同参数 ⇒ 逐字节相同"不成立，两轮 diff 里每一行都在动
- JSON 的键序**没有语义**，所以规范化不丢信息；它只是把**不该属于判据的自由度**收掉
- 你不必照着这个顺序写参数 —— 写什么顺序都行，**落盘时统一**

## 3.10 图纸（`sheet.svg`）：复核的**唯一对象**，而且必须在贵的那一步之前看

六张分图放在一起时，人看到的是六个数；**排到一张图纸上**之后，"第三角法的左视图在左、俯视图在上"
这件事才在图上**可见** —— 排错了会被一眼看出来，而分图永远看不出来。这是它的全部理由：
**把复核提前到 ④ 之前**，而 ④ 是唯一贵的一步（要开 Blender）。

图纸上有什么、以及**能据它判断什么**：

| 图上事实 | 能回答的问题 |
|---|---|
| 六视图的**格位**（`cells` 里的 `col`/`row`） | 第一角法 / 第三角法**真的换了排布**没有（第三角法左右、上下都反 —— GB/T 17451 / ANSI Y14.3） |
| 标题栏里的**全图比例尺**（`shared_scale`） | 六张视图是否**共用同一个比例尺**。逐视图自适应缩放在工程图上是**错误**，不是风格选择 |
| 每个对象的矩形与名字、每视图的 `extent u/v` | 体量个数、大小排序、比例（**粗粒度、人眼级**，不是测量） |
| 红框（虚线） | 该视图的包络 |

**它做不到什么**（必须一起说出去）：形状对不对 —— 图纸是线条与数字，判 "这像不像照片里的那件东西"
仍然是人的眼睛（`photo_check` 只把比例变成可核对的数字）。

**怎么拿到它**

- **文件**：`agh_ortho_save` 落盘，`report.json` 的**第一个**描述符就是 `sheet.svg`（`save` 不需要 Blender，所以"候选轮"也能落）
- **文本**：`agh_ortho_views` 的 `sheet_svg.svg`（同样是一整张图，含全图比例尺与格位）

**顺序硬规矩**：`fit` 给出 `verdict=fit` 之后，**先** `save` 一次候选（`run_id` 带 `-candidate`）、
人打开 `sheet.svg` 复核、**通过后才 `apply_ops`**。候选与交付用**两个不同的 `run_id`**（见 §1）。

### 3.12 网格路（外部生成的网格）

- **进场**：`.agnes/agh-ortho/meshes/<名字>/{mesh.glb, source.json}`；`source.json` 声明 `unit / upAxis / declaredHeight`。
- **mesh 项的 `w/d/h` 不是自由的**：必须是**文件自己的比例** —— `mesh.import.scale` 是**标量**（只能等比缩放），
  它只能对上高度、对不上截面。声明与实测不符即 **blocking**。
- **四条闸门**（都在 `save` 里，**键在项自己的 `path` 上**，不依赖 `mesh_file` 入参）：
  `E_MESH_SOURCE_UNREADABLE`（缺 sidecar）/ `E_MESH_SOURCE_MISMATCH`（sidecar vs 参数）/
  `E_MESH_SIZE_MISMATCH`（参数 vs 实测）/ `E_MESH_DECLARED_HEIGHT_MISMATCH`（**文件自己的声明 vs 实测**）。
  另：`E_MESH_MEASUREMENT_LIMITED` —— 节点带**旋转**时拒绝给尺寸判定（宁可说"量不了"）。
- **两条 op**：`mesh.import`（只发 `path/name/upAxis/scale/size`；`size` 是**期望值**，下游会比对回报，
  **不施加**）+ `object.transform`（真正摆放）。
- **形状没有任何一档能验**：只有存在 / 类型 / 位置 / 尺寸被断言，形状必须人眼看 `sheet.svg`。
- **安装后必须核**：`package status` 到 `actual=running` 再开新对话 —— 否则新会话里整包工具不存在
  （实测症状：工具清单里没有 `agh_ortho_*`）。

### 3.13 两个可选输入：`silhouette` 与 `image_file`

两个都是**便宜且立刻可验**的档，建议在收敛那一轮一起给上：

- **`silhouette: { path, ortho_scale, sensor_fit }`** —— 一张**带透明通道**的正交渲图，多一档**可判**的
  "轮廓像不像"：剪影折算成米后**同时**与 `outline`（几何自洽）和 `photo_check`（像不像照片）比。
  - **`ortho_scale` 必填**：它是像素↔米的唯一依据，缺了就没有判定（不是"跳过"）。
  - **贴边即 blocking**（`E_SILHOUETTE_CROPPED`）：被裁的图会给出**看起来合法**的数 —— 下游实测过一个
    2.0 m 的物体量成 1.2 m。
  - 容差按**渲染分辨率**推（≥2 像素折算），所以别用高分辨率空盼更高精度。
  - 图从哪来：下游 `camera.add{type:"ORTHO", ortho_scale}` + `render.still{transparent:true}`；
    或人在 Blender GUI 里手渲一张（`Film > Transparent` 开）。
- **`image_file`**（源照片的真实路径）—— 核对参数里声明的 `source.input_image_sha256`：
  - **声明了却不给文件 = blocking**（没有东西能核的声明就是装饰）；
  - 相符才通过，并把**源图登记进交付包** ⇒ "这张图 → 这个网格"第一次是可核的事实。

（两档都进 `fit` 的 verdict，也都进 `save` 的 `report.json.checks`；读不到都是**明确 blocker**，不是"没发生"。）

### 3.14 网格路实测口径（`mesh-triposr-4` 之后）

- **`upAxis` 记的是"内容真值"，不是文件扩展名/规范**：TripoSR 导出 GLB 时节点变换是**恒等**，而它自己的渲染器用 `up=[0,0,1]` ⇒ **内容其实是 Z-up，却顶着 glTF 的 Y-up 名义**。声明必须写内容真值，否则导入后会躺下，而尺寸闸门还会拿错轴去比。
- **声明的精度决定容差**：参数写 4 位小数（0.9638）时，容差不可能是 1e-5 —— 见 §9.24 第 2 条。`mesh_measured` 会同时印出 `relative_tolerance` 与实测差，读的时候比一比。
- **整数写法 ≠ 舍入过的测量**：`2` 不许被读成 ±0.5。
- **`scale_asserted: false` 是正常的**：导入网格的 scale 来自文件自身节点变换，emit 阶段不读文件 ⇒ 那一行只断言存在/类型/位置。别把它读成"验失败了"。
- **比例不是米**：网格路同样要 `scale_anchor` 或显式 `proportions_only`；`h.v` 与 sidecar 的 `declaredHeight` 之比才是缩放倍数。
- **形状仍然没有任何一档能证**：numeric 只证自洽、readback 只证下游照做；要"像不像"得靠人眼（图或 `render.still` 的剪影 → 交给 `silhouette` 档做数值比对）。

## 4. 归因纪律：⑤ 失败时**默认不要改参数**

失败有三种方向，应对完全不同：

| 失败 | 含义 | 该怎么办 |
|---|---|---|
| `②` validation / numeric 不过 | **参数本身不对** | 改参数 ✓ |
| `③` 形态与照片不符 | **参数不对**（或参照物不对） | 改参数或换参照物 ✓ |
| `⑤` 场景与参数不符 | 参数**可能是对的** | ⚠️ **先归因** |

`⑤` 不一致只有两种原因：

1. **我们发出的 ops 与自己的参数不一致** → 这是**本插件的 bug**。报出来，**不要靠调参数去掩盖**。
2. **场景与 ops 不一致** → **下游没照做**（或语义分歧）→ 记进 `DOWNSTREAM-REQUEST-readback.md`，也不改参数。

`fit` 的 `revise_hints` 里对这两类会**明确写 "do NOT tune the parameters"**，读回块里还有 `attribution` 字段讲同一条。
**为迎合一个出错的现场去改参数，会把正确的模型改歪，而且掩盖真正的 bug。**

---

## 5. `conf` 的正确用法

`conf` 是**模型声明的相对把握**，**不是校准过的概率**。

- ✓ 用来排序：把 `least_certain_first` 里最靠前的几个尺寸拿去复核、或和照片再对一次。
- ✗ **不要**当阈值：「`conf > 0.8`」不等于「80% 正确」。任何基于它的自动过滤都是在自欺。

---

## 6. 停机规则（防止无限循环）

1. **②③ 通过、且 ③b 的图纸被人看过之前，不许进 ④** —— 便宜的线不过，绝不付贵的开销。
2. **⑤ 失败只允许再来一轮**。再来仍失败 ⇒ **停下**，把 `blocker` 与人需要的决定摆到人面前。
3. 每轮必须带**具体修改指向**（`revise_hints` 给了）。没有指向的循环是随机游走。
4. ②③ 最多迭代 N 轮（建议 5）；到顶就停下问人，而不是继续猜。

---

## 7. 三条"证明不了"的边界（必须随结论一起说出去）

1. `numeric` **只证明自洽**，不证明与照片有关系。
2. `scene_readback` **只证明下游照做了、尺寸对**，同样不证明与照片一致。
3. **图像级比对做不到**：下游没有相机 op，而且模型看不见工具产出的图像素。
   所以"像不像原照片"这件事，**只能靠人**（加上 §1 的 `outline` 粗核对）。

**名字不能骗人**：`scene_readback` 就是一档半，它不叫 `against_blender`。

## 8. 一条完整的命令序列（每轮 / 收敛后）

**每轮（便宜）**
```
agh_ortho_fit { <参数 JSON> }
```

**verdict=fit 之后、进 ④ 之前（便宜：不碰 Blender）—— 复核图纸**
```
agh_ortho_save { <同一组参数>, "run_id": "<名字>-candidate" }
```
打开 `report.json` 的第一个描述符指向的 `sheet.svg`，看排布/比例尺/体量个数与形态（§3.10）。
**不像 → 回 ①**；像 → 才允许进下面这一段。

**收敛后（贵，只跑一次）**
```
agh_blender_start { "empty": true }        ← 清掉出厂 Cube/Light/Camera，于是 .blend 与 ops.json 描述同一件事
agh_blender_apply_ops { "ops": <上一步 fit 返回的 ops，原样> }
agh_ortho_fit { <同一组参数>, "against_scene": true }
agh_blender_capture { "width": 1600, "height": 1200 }
agh_blender_export { "destination": "<工作区>/outputs/<名字>.blend" }
agh_ortho_save { <同一组参数>, "run_id": "<有意义的名字>", "scene_file": "<上面那个 .blend 的绝对路径>" }
agh_blender_stop { "force": true }
```

- `scene_file` 让 `save` 把那个 `.blend` **登记**成第 11 个产物（按**原始字节**算 sha256/bytes，**不复制**）：
  包里因此第一次有了"模型本身"。读不到它是 `E_SCENE_FILE_UNREADABLE`（blocker），**不是**悄悄没有。
- `agh_blender_capture` 渲的是**当前 GL 视口（透视）**，不是正交六视图 —— 别拿它和 `sheet.svg` 比。
  工具**从不**把图片放进结果（实测那样会让这一轮直接失败并毒化会话），图只能由人打开看。
- `agh_blender_export` 的 `destination` **必须是不存在的路径**（它绝不覆盖）；导出走 staging 副本、
  `mainFileUntouched: true`（Blender 主文件全程没被写过）。**但**场景里仍有 `--factory-startup`
  的 Cube/Light/Camera，它们**也会被写进 `.blend`**（ops 里没有删除指令）—— 打开时会多一个
  2×2×2 的方块与一盏灯，那不是我们的模型。

- `apply_ops` / `save` / `stop` 都可能要人批准（`stop` 在有未保存改动时**会拒绝**，除非 `force: true`；这些实例是 `--factory-startup` 的一次性场景，丢弃没有损失）。
- `save` **先落盘 report.json 再返回** —— 消费者以磁盘上的 `report.json` 为准，不以返回值或转述为准。

## 9. 现在能做到什么 / 做不到什么（交付时别夸大）

**能**：一批带置信度的尺寸参数 → 可审计的 ops → 六视图（含数值轮廓，外加**一张图纸**：六视图同图、全图一个比例尺）→ 真实 Blender 场景 → 读回确认（名字/类型/位置/缩放/**尺寸**）→ 带 sha256 的产物包（10 个描述符，第一个就是那张图纸）。

**不能**：
- 从图片**自动**推参数（看图和写参数是模型的活，工具不做感知）
- 照片级的**网格重建**（这条路刻意选了"参数是唯一真值源"）
- 挖洞、挤出、旋转体（下游没有 boolean/extrude/revolve）
- 与照片的图像级比对

形体的表达边界只有六种轴对齐基元；表达不了的东西会以 `downstream_cannot` / `emitter_not_yet` / `unresolved` **一路传到读者面前**，不会静默丢失。
