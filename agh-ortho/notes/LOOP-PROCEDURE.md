# agh-ortho 闭环规程（v1）

这份文件写给**在这个工作区里工作的 agent（模型）**，以及在旁边看的人。
它把"照片 → 参数 → 验证 → 建模 → 交付"这个循环写成**可复现的步骤**，而不是靠口述。

设计依据：`CONTRACT.md`（参数化优先、三态、双档校验）、`SKELETON-STATUS.md`（实测结论）、
`DOWNSTREAM-REQUEST-readback.md`（下游缺口）。

---

## 0. 角色分工（先认清谁做什么）

| 步骤 | 谁做 | 为什么是它 |
|---|---|---|
| **① 看图 → 候选参数** | **模型** | 只有模型看得见**用户上传的照片**。工具看不见任何图像（上游契约 §2.3 实测：工具产出的图连模型也看不见）。所以**不要**试图让某个工具去"分析图片" —— 它只能编造观察。 |
| **② 自检（便宜）** | **`agh_ortho_fit`** | 纯计算、零依赖、不需要 Blender。挡掉绝大多数低阶错误。 |
| **③ 形态粗核对** | **模型 + 人** | 模型同时握着两样东西：照片 + `outline`（视图的数值轮廓）。这是照片一致性**唯一可行的自动路径**，代价为零。 |
| **④ 建模** | **`agh_blender_apply_ops`** | 真的写进场景。 |
| **⑤ 读回验证（贵）** | **`agh_ortho_fit` + `against_scene: true`** | 唯一能证明"下游真的照做了、尺寸也对"的检查。 |
| **⑥ 交付** | **`agh_ortho_save`** | 落成带 sha256 的产物包。 |
| **批准** | **人** | `apply_ops` / `save` / `stop` 声明为需要同意（若会话开着 YOLO 则静默执行 —— 要知道当前模式）。 |

---

## 1. 两段式：便宜的每轮跑，贵的只跑一次

```
①  模型看图 → 参数 v_n
②  fit（不带 against_scene）                        ← 每轮都跑，零成本
      verdict=revise → 按 revise_hints 改，回 ①
      verdict=fit    → 进 ③
③  模型+人：拿 outline 与照片粗核对                  ← 每轮都跑，零成本
      形态不符 → 回 ①
④  agh_blender_start → agh_blender_apply_ops { ops: <fit 返回的 ops> }
⑤  fit { 同一组参数, against_scene: true }           ← 只跑一次，贵
      失败 → 先归因（见 §4），再决定改什么
⑥  agh_ortho_save { 参数, run_id } → agh_blender_stop { force: true }
```

**迭代的对象是参数，不是六视图。** 六视图是参数的投影；改参数才可能让视图变对，光看视图不会。

---

## 2. 每一轮该看 `fit` 的哪些字段

| 字段 | 怎么看 |
|---|---|
| `verdict` | `fit` 才允许进下一步。`revise` 时**不要**申请 apply_ops。 |
| `revise_summary.blocking` | > 0 必须处理；`warning` 可留但要自知 |
| `revise_hints[]` | **逐项逐轴**。每个 hint 的 `where` 就是该改的位置。**一轮只改被点名的那些**，别顺手动别的（否则无法归因是哪一步改好的）。 |
| `validation.checks[]` | 每条带自己的 `ok`。失败项就是具体的原因。 |
| `three_state` | `downstream_cannot`（只能删或在 `unresolved` 里声明）/ `emitter_not_yet`（等 lowering）/ `declared_by_author` / `needs_attention`（未知特征或未决形状 —— 要处理） |
| `numeric.residual_max` | 必须为 0。不为 0 时**看 §4**。 |
| `outline` | **③ 的输入**。逐视图、逐对象的 `u_m` / `v_m` 与 `w_over_h`。拿它和照片比比例、体量个数、大小排序。 |
| `declared_relative_confidence` | 只用来**排序**（哪个尺寸最没把握）。见 §5。 |
| `anchor` | 没有它（且没声明 `proportions_only`）就是 blocking。见 §3。 |
| `ops` | `verdict=fit` 时，这就是要喂给 `agh_blender_apply_ops` 的东西，**原样传**。 |

## 3. 缺 `scale_anchor` 是**必须修**的，不是可选

单张照片只有一个投影方向，深度与遮挡天生有歧义。所以**绝对尺寸的唯一来源**是一个已知真实长度：

```json
"scale_anchor": { "pixel_len": 340, "real_len": 2.1, "ref": "door_height" }
```

- 门 ≈ 2.1 m、砖、人、A4 纸、足球门 —— 任何你**确实知道**长度且能在照片里量出像素数的东西。
- **脆弱性**：所有绝对尺寸都乘同一个比值。参照物认错、或 `pixel_len` 读偏 10%，**每一个尺寸都偏 10%**。
  这不是可以忽略的误差 —— 它意味着**整份模型等比例地错**。
- 如果只要比例、不要绝对尺寸：显式写 `"assumptions": ["proportions_only"]`。
  **不声明就当作缺锚点处理** —— 因为不声明的话，一批看起来很有信心的"米"其实没有依据。

## 4. 归因纪律：⑤ 失败时**默认不要改参数**

失败有三种方向，应对完全不同：

| 失败 | 含义 | 该怎么办 |
|---|---|---|
| `②` validation / numeric 不过 | **参数本身不对** | 改参数 ✓ |
| `③` 形态与照片不符 | **参数不对**（或参照物不对） | 改参数或换参照物 ✓ |
| `⑤` 场景与参数不符 | 参数**可能是对的** | ⚠️ **先归因** |

`⑤` 不一致只有两种原因：

1. **我们发出的 ops 与自己的参数不一致** → 这是**本插件的 bug**。报出来，**不要靠调参数去掩盖**。
2. **场景与 ops 不一致** → **下游没照做**（或语义分歧）→ 记进 `DOWNSTREAM-REQUEST-readback.md`，也不改参数。

`fit` 的 `revise_hints` 里对这两类会**明确写 "do NOT tune the parameters"**，读回块里还有 `attribution` 字段讲同一条。
**为迎合一个出错的现场去改参数，会把正确的模型改歪，而且掩盖真正的 bug。**

---

## 5. `conf` 的正确用法

`conf` 是**模型声明的相对把握**，**不是校准过的概率**。

- ✓ 用来排序：把 `least_certain_first` 里最靠前的几个尺寸拿去复核、或和照片再对一次。
- ✗ **不要**当阈值：「`conf > 0.8`」不等于「80% 正确」。任何基于它的自动过滤都是在自欺。

---

## 6. 停机规则（防止无限循环）

1. **②③ 通过之前，不许进 ④** —— 便宜的线不过，绝不付贵的开销。
2. **⑤ 失败只允许再来一轮**。再来仍失败 ⇒ **停下**，把 `blocker` 与人需要的决定摆到人面前。
3. 每轮必须带**具体修改指向**（`revise_hints` 给了）。没有指向的循环是随机游走。
4. ②③ 最多迭代 N 轮（建议 5）；到顶就停下问人，而不是继续猜。

---

## 7. 三条"证明不了"的边界（必须随结论一起说出去）

1. `numeric` **只证明自洽**，不证明与照片有关系。
2. `scene_readback` **只证明下游照做了、尺寸对**，同样不证明与照片一致。
3. **图像级比对做不到**：下游没有相机 op，而且模型看不见工具产出的图像素。
   所以"像不像原照片"这件事，**只能靠人**（加上 §1 的 `outline` 粗核对）。

**名字不能骗人**：`scene_readback` 就是一档半，它不叫 `against_blender`。

---

## 8. 一条完整的命令序列（每轮 / 收敛后）

**每轮（便宜）**
```
agh_ortho_fit { <参数 JSON> }
```

**收敛后（贵，只跑一次）**
```
agh_blender_start
agh_blender_apply_ops { "ops": <上一步 fit 返回的 ops，原样> }
agh_ortho_fit { <同一组参数>, "against_scene": true }
agh_ortho_save { <同一组参数>, "run_id": "<有意义的名字>" }
agh_blender_stop { "force": true }
```

- `apply_ops` / `save` / `stop` 都可能要人批准（`stop` 在有未保存改动时**会拒绝**，除非 `force: true`；这些实例是 `--factory-startup` 的一次性场景，丢弃没有损失）。
- `save` **先落盘 report.json 再返回** —— 消费者以磁盘上的 `report.json` 为准，不以返回值或转述为准。

---

## 9. 现在能做到什么 / 做不到什么（交付时别夸大）

**能**：一批带置信度的尺寸参数 → 可审计的 ops → 六视图（含数值轮廓）→ 真实 Blender 场景 → 读回确认（名字/类型/位置/缩放/**尺寸**）→ 带 sha256 的产物包。

**不能**：
- 从图片**自动**推参数（看图和写参数是模型的活，工具不做感知）
- 照片级的**网格重建**（这条路刻意选了"参数是唯一真值源"）
- 挖洞、挤出、旋转体（下游没有 boolean/extrude/revolve）
- 与照片的图像级比对

形体的表达边界只有六种轴对齐基元；表达不了的东西会以 `downstream_cannot` / `emitter_not_yet` / `unresolved` **一路传到读者面前**，不会静默丢失。
