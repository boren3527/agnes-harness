# 上游插件 → 产物契约（UPSTREAM-ARTIFACT-CONTRACT）

| 项 | 值 |
|---|---|
| 文档状态 | **草案 · 待双方确认** |
| 建立时间 | 2026-10-08 |
| 适用双方 | **生产方**：上游插件（产出文件/产物） · **消费方**：AGH agent（本仓库这套插件工作栈） |
| 依据 | 本机实测（见 `P0-EVIDENCE.md` 与本文 §2 的引用），非推测 |
| 版本 | 契约版本 `1`（描述符里带 `contract: 1`，不兼容变更必须递增） |

**读法**：标 `【实测】` 的条目有本机证据支撑，违反会**可复现地**坏掉；标 `【约定】` 的条目是双方要一起守的设计决定。

---

## 1. 范围与非目标

**范围**：上游插件产出的文件/产物**如何被描述、落盘、登记、消费**。

**非目标**（明确不做，别在实现里绕）：

- ❌ 不通过"内容块 / 内联数据"把产物交给模型（见 §2.1）
- ❌ 不要求消费方理解产物的**二进制语义**（图片像素、专有格式内部结构）
- ❌ 不由本契约规定上游插件**怎么生产**产物（那是它自己的事）

---

## 2. 三条硬边界（违反即坏，均由实测得出）

### 2.1 ❌ 产物绝不能以"内容块"形式进入工具结果

**【实测】** AGH 的请求媒体面只接受来自 `tool:computer_use` 通道的产物。任何由**第三方插件**放进工具结果的内容块（尤其图片）：

1. 读不回来 → 该轮以 `E_STEP_FAILED: artifact <sha> could not be read` 失败；
2. **该会话被永久毒化** —— 之后任何一句输入都会在 40 ms 内以同一错误失败，无法挽救；
3. 失败是**终局性**的：没有重试、没有降级。

**实测两次**，第二次是模型主动传 `inline: true` 触发的 —— 所以**"默认关闭"不算防护，必须让这条路不存在**。

> **契约要求**：生产方**永不**把产物作为内容块返回；消费方**永不**请求内联。产物只以**路径 + 元数据 + 文字语义**交付（§3）。

### 2.2 ❌ "写进产物库" ≠ "消费方读得到"

**【实测】** 产物字节写入存储（`<dataDir>/artifacts/sha256/xx/<sha>`）**不代表**可读；可读还需要写进归属索引（`PersistentArtifactReadAuthorityIndex`，由 `ArtifactAuthorityProjectionWriter` 投影）。缺失登记时读请求被拒，报错**不说明原因**，并且同样导致 §2.1 的终局性失败。

> **契约要求**：**不要用 AGH 的 artifact seam 做交付**。写**真实文件**到磁盘，报路径。这一条把 §2.2 整类问题消掉。

### 2.3 ⚠️ 图片：消费方**看不到像素**

**【实测】** 工具产出的图进不了模型；能进模型的只有**用户自己上传**的图（inline block）。

> **契约要求**：若产物是图片，**`preview` 或 `text` 字段必须承载它的语义**（生产方负责把"图里是什么、测出了什么"写成文字）。人要看图 → 由人打开路径或前端面板展示，**不要指望模型看图**。

## 3. 产物描述符（双方唯一交换的载荷）

生产方**每次产出**都返回一个描述符数组；消费方只认这个结构。

```jsonc
{
  "contract": 1,                    // 必填：契约版本（整数）
  "id": "0f2b9c1e-…",               // 必填：幂等键，UUID
  "path": "D:\\work\\out\\0f2b….csv", // 必填：绝对路径，文件必须已落盘
  "sha256": "…64 hex…",             // 必填：文件内容摘要（消费方会复核）
  "bytes": 123456,                  // 必填：字节数
  "mime": "text/csv",               // 必填
  "kind": "csv",                    // 必填：image | text | json | csv | blend | archive | other
  "createdAt": "2026-10-08T03:41:00Z", // 必填：ISO-8601
  "producer": "their-plugin/1.2.0", // 必填：产出者标识（便于归因与兼容处理）

  "preview": "12 列 × 340 行测量表；列名：t,x,y,…",  // 必填（!）：给人也**给模型**的一句话语义
  "text": null,                     // 可选：若 kind=text/json/csv，可直接给内容（≤64 KiB）
  "meta": { "rows": 340, "columns": 12 }  // 可选：结构化补充（消费方可选读）
}
```

### 字段规则

| 字段 | 必填 | 规则 |
|---|---|---|
| `contract` | ✅ | 整数。消费方**不认识的版本必须明确拒绝**，不许猜 |
| `id` | ✅ | UUID。**同一 `id` 必须对应同一内容**（幂等） |
| `path` | ✅ | **绝对路径**；返回时文件**必须已完整落盘**（不是"将要写"） |
| `sha256` | ✅ | 小写 hex，64 位。消费方**复核**，不符即判该产物无效 |
| `bytes` | ✅ | 与磁盘一致 |
| `preview` | ✅ | **≤200 字符**，一句话说清"这是什么、能用来干什么"。**这是模型唯一必然能读到的内容** |
| `text` | ⭕ | 仅小文本（≤64 KiB）。大文件**只给路径**，不要塞内容 |
| 其他 | ⭕ | 允许扩展，但**消费方必须能忽略未知字段**（向前兼容） |

## 4. 落点与命名（【约定】）

```
<root>/                        ← 生产方每次运行一个 UUID 子目录，避免相互覆盖
  <run-uuid>/
    marker.json                ← 归属标记：{ "contract":1, "producer":"…", "runId":"…", "createdAt":"…" }
    report.json                ← 本次运行的描述符数组（先落盘，再返回，见 §5.2）
    <artifact files…>
```

- 目录**由生产方拥有**；消费方**只读**，不删不改。
- `marker.json` 用于**归属校验**：消费方在吃一个产物前，先确认它属于预期的生产方与运行，避免"读到别的运行留下的东西"。

---

## 5. 写入语义（【实测】+【约定】）

### 5.1 永不覆盖

**【实测】** Host 的 `fs.write` 会对**已存在**的目标做 checkpoint；并会**拒绝**前 8192 字节含 NUL 的既有文件（即二进制）。因此产物的**最终目标永远是新的 UUID 文件名**。

> **要求**：覆盖语义一律用"写新文件 + 在报告里说明取代关系"，不要就地改。

### 5.2 先落盘报告，再返回

**【实测】** 副作用型工具的结果可能被宿主替换为 `TOOL_OUTCOME_UNKNOWN`（结果**与失败原因一起永久丢失**）。唯一可靠的补救：**先把报告写到磁盘**（`<run-uuid>/report.json`），返回值只是"方便读的副本"。

> **要求**：`report.json` 必须包含 §3 的完整描述符数组。消费者以**磁盘报告**为准，不以返回值或模型转述为准。

### 5.3 幂等

同一 `id` 重复请求 → 返回**同一描述符**（同 `path`/`sha256`），不重新生成。

---

## 6. 错误码与失败语义（【约定】，但按我们的教训写）

| 码 | 含义 | 可重试 | 必须带 |
|---|---|---|---|
| `E_UNSUPPORTED_CONTRACT` | 消费方不认识 `contract` 版本 | 否（先升级） | 双方版本号 |
| `E_ARTIFACT_MISSING` | 路径不存在 / 未落盘就返回 | **是** | 期望与实测的 `sha256` |
| `E_ARTIFACT_MISMATCH` | `sha256` 或 `bytes` 不符 | 是 | 期望值、实测值 |
| `E_ARTIFACT_UNREADABLE` | 权限/占用等原因读不到 | 是 | 具体路径 + 系统错误 |
| `E_RUN_NOT_OWNED` | 产物不属于该生产方/该运行 | 否 | `marker.json` 的实际内容 |

**通用要求**：

1. **错误必须带可操作的提示**（"用 X 替代 Y"），不能只回一句"参数不匹配"。
   **【实测】** 我们被一个**没有任何提示**的 `TOOL_ARGS_INVALID` 卡了整整一轮。
2. **拒绝 ≠ 失败**：拒绝要能区分（我们用的是"409 + 专用码"），调用方据此决定要不要换参数重试。
3. **部分成功必须显式表达**：`{ ok:false, produced:[…], failed:{ index, code, message } }`，不许假装整批成功。

---

## 7. 清理与保留（【约定】）

- **谁删**：**生产方**。消费方永不删别人的产物。
- **保留**：默认保留最近 **N=20** 次运行（或 M=30 天，取先到者）。长期产物需在生产方侧显式声明"保留"。
- **不得静默删除**被引用的运行（引用 = 该运行出现在某次会话的报告里）。

> **【实测】** 不设这条会变成"每次运行留一个目录"，长期累积且无人清理。

---

## 8. 消费方（AGH agent）如何使用它

1. 读 **`report.json`**（不是返回值、不是转述）。
2. 对每个描述符：**复核 `bytes` 与 `sha256`**；不符 → 按 §6 拒绝。
3. **只用 `preview` / `text` / `meta` 做推理**；需要正文时用文件工具按 `path` 读（**文本类**可行）。
4. **图片不读像素**（§2.3）：把 `preview` 当语义来源，或请人看图。
5. **不做任何写入/删除**：只读。
6. 若 `contract` 不认识 → 明确拒绝并回报版本，**不猜**。

---

## 9. 验收（怎么证明这条链真的通了）

最小闭环，全部可独立复核：

| 步 | 动作 | 通过判据 |
|---|---|---|
| 1 | 生产方产出 1 个文本类产物（如 csv） | `report.json` 存在；`path` 指向真实文件；`sha256` 与磁盘一致 |
| 2 | 消费方读 `report.json` 并复核摘要 | 摘要一致，无 `E_ARTIFACT_MISMATCH` |
| 3 | 消费方按 `path` 读正文 | 读到的内容与 `text`/`preview` 描述一致 |
| 4 | 生产方产出一个**图片**产物 | 描述符里 `preview` 有实质语义（不是"一张图"这种废话） |
| 5 | 消费方**只**用 `preview` 说明它 | 说明与人类看图结论一致（人能核对） |
| 6 | 重复请求同一 `id` | 返回同一描述符，不重新生成 |
| 7 | 人为改坏一个 `sha256` | 消费方**拒绝**并报 `E_ARTIFACT_MISMATCH`（不是静默接受） |
| 8 | 反例：把图片作为内容块返回 | **必须做不出来** —— 若做得到，说明 §2.1 没落实 |
