# AKA 小车建模快速演示

已接入同事提供的 `agh-modeling-20261010-2017.zip`：

- `../packages/agh-blender`：受管理的本机 Blender、网格导入、渲染和 `.blend` 导出。
- `../packages/agh-ortho`：调用外部图片生成网格程序、读取真实网格尺寸、记录来源与复核报告。
- 小车插件 `aka_model_object` 留档当前主体原图；优先由 `agh_ortho_surface_ops` 表达形状并检查六视图，再用 `agh-blender` 建模、返回真实材质渲染和导出。复杂外形可补充图片模型参考；已有网格生成器时也可用 `aka_build_model`。

原插件 LICENSE / NOTICE / Blender 桥接代码 GPL 声明均保留。附带的 scripts/cloud 是原包参考工具，不会自动执行；其中历史机器路径不作为本项目配置。未带入原包的机器配置、模型权重或安装环境。

## 配置和使用

1. 在 AGH 插件管理中从本地源码安装并启用 `examples/packages/agh-blender`、`examples/packages/agh-ortho`，并更新已安装的小车插件源码版本。走现有插件安装/更新入口，构建或重启不会自动更新已固定的插件快照。
2. 本机安装 Blender 4.2 或更新版本。杯子等适合曲面参数的物体不需要外部网格生成器；图片转 GLB 是另一条可选路线，需要生成器自己的 Python 环境和权重。
3. 需要图片辅助时，打开「设置 → 模型与账户 → 图片生成模型」，选择 `qwen-image-2.1-pro`、填写对应 API Key、选择 1K 或 2K 并启用图生图，再保存。密钥不回显，也不写入工作区；保存不调用生图接口。不要配置 Agnes 作为本演示的兜底。
4. 常规静止建模不需要 `aka_modeling_configure`。只有使用已安装的图片转网格生成器时，才保存下述生成器配置；提供真实程序、参数、轴向和单位，不猜路径。Blender 路径可选，留空按现有插件查找。
5. 用 `aka_model_object` 拍当前方向，按原图确认主体并详细描述，`capture_subject` 留档这张图。优先用 `agh_ortho_surface_ops` 检查六视图，再执行 Blender 白名单操作；同参数 `scene_readback=true` 核对场景，最后 `agh_blender_capture` 指定已有相机，返回真实材质图片并导出。这条路线不转向、不前进、不操作夹爪。复杂物体可用 `aka_generate_reference_views` 先生成正面，再并行生成右、后、左三张；用 `aka_read_reference_views` 分两步查看并分析。推测视角不能当作实拍证据或准确尺寸。

生成器配置保存在选定设备工作区的 `.agnes/agh-ortho/mesh-run.json`，任务直接读取同一文件。必须有 `generator`、`command` 参数数组、实际 `upAxis`、`unit` 和 `displayHeight`（0.01—10 米的展示高度）；可选 `preprocessCommand`、`output` 和 `blenderExecutable`。`command` 必须包含 `{image}` 或 `{prep}`，以及 `{out}`；占位符遵循原插件约定。密钥使用运行环境，不能写进命令参数或配置文件。参考 scripts/cloud 不会自动安装环境、下载权重或启动服务。

产物：原图、来源清单和透明主体缓存位于 `.agh-device/exports/<taskId>/`；主体预览位于 `.agh-device/subjects/`；GLB 和来源记录在 `.agnes/agh-ortho/meshes/<runId>/`；`subject.png`、预览 PNG、`model.blend`、流程报告在 `.agh-device/models/<runId>/`；原插件复核产物在 `.agnes/agh-ortho/runs/<runId>/`。失败报告会指出停在哪一步，已有生成物保留。

已有四张采样照片之后，主体生成和建模不会移动小车，不需要再拍一轮。明确要跳过图片服务时，给 `aka_build_model` 传 `prepareSubject: false`，恢复直接用所选原图生成网格的流程。

## 三个录制案例

录制前先更新 AGH 和已安装的本地插件快照。图片生成模型与会话模型是两项配置：会话必须选择能读图片的模型，才能查看小车原图和 Blender 截图；图片生成模型负责去背景参考图。先配置图像识别、确认额度并打开连续识别。相机画面在控制台显示，但相机开启本身不会开启收费识别。断电后使用「恢复连接和画面」，无需解绑；此按钮不重启识别、不恢复中断任务。

| 案例 | 前置条件 | 正常执行顺序 | 停止条件 |
| --- | --- | --- | --- |
| 找网球 | 相机和连续识别已开启；识别服务能识别样品类别 | `aka_observe` → `aka_find`：当前照片识别 → 未找到则短转向 → 停车后的新照片识别 → 找到即停止、返回原图 | 额度耗尽、10 秒内无新识别、连接丢失；有限观察范围未找到就报告未找到 |
| 捡球投放 | 地面、运动、抓取窗口、持物及落点区域已实测保存；已保存 delivery 路线；投放位置能在新图中识别；现场监督且路线清空 | `aka_mission_saved`：核对目的地 → 寻物 → 接近 → 夹取并观察 → 按保存路线搬运并逐段观察 → 释放并观察 | 目标/目的地歧义、超出标定、持物丢失、动作未知；不自动重复机械臂动作 |
| 四面照片建模 | 固定简单物体、清空环绕路线、地面与运动标定；图片模型已配置；Blender 与建模插件已启用 | `aka_orbit_capture` → 四张原图及识别记录 → 描述可见形状、颜色与比例 → `aka_prepare_subject` → 建模 → `agh_blender_capture` 对照参考图 → 导出 `.blend` | 视角/目标核对失败、透明主体无法确认、生成器/Blender 缺失、截图发布失败 |

可用的录制提示词（类别和路线由已保存配置及实际识别决定）：

1. 「帮我找附近的网球。先核对设备和识别状态，在有限观察范围内转向拍照识别，找到后停车并给我看原图；若只有通用球类结果，请看原图确认，不确定就说明。」
2. 「我在现场监督，搬运路线已清空。按已保存的投放路线把球夹起来送到垃圾桶再释放。每阶段核对新照片，不确定就停止，不要重复抓取。」
3. 「我在现场监督，物体固定，环绕路线已清空。拍四面原图，根据原图描述细节和估计比例，生成无背景参考图，再调用现有插件在 Blender 建模。看实际渲染截图修正后导出工程，没有尺度参照不要写成实测尺寸。」

网球类别必须以真实服务结果为准；通用 `ball` 检测不证明一定是网球。投放只支持机械臂释放，未实现抛掷；视觉候选不等于已成功夹住或落入桶内。云端检测提供类别、置信度和边框，详细描述由会话模型结合原图完成，不能假称检测接口提供精确尺寸。

建模有两条路线：常规路线按原图用 `agh_ortho_surface_ops` 表达曲面、检查六视图，执行 Blender 白名单操作后读回并查看真实渲染；图片辅助只在形状需要时使用。有真实图片转网格生成器时也可用 `aka_build_model` 自动串联。数值校验不代替外形比较，生成的四视角也不等于多视图几何重建。

确认主体后立即留档的新格式静止建模原图，以及已生成参考图，可以在插件重载或进程重启后恢复。恢复会核对原会话、设备绑定、配置版本及图片摘要；不恢复任何运动任务。旧格式缺少归属信息的档案、绑定已改变的档案或损坏图片会明确拒绝，不为恢复状态自动收费生图或移动小车。请求发送标记在调用图片服务前落盘；结果未知且没有缓存时不能自动重发。更新后先保存并关闭旧 Blender，再启动新的受管理实例。

事件流应显示停车观察、有限转向、任务阶段以及建模 1/6—6/6；有错误时检查具体缺项。上述流程在离线测试中使用模拟识别、运动和 Blender 回执验证，未做实车、真实收费 API 或真实 Blender 联调。

继承 `base` 的预设为接近、搬运、巡逻、任务及环绕工具配置 200 秒上限；主体生成 200 秒、网格生成 600 秒、完整建模 900 秒。普通工具仍是 120 秒。`costHint` 不会延长执行期限，已经打开的会话沿用原来的预设。网格生成使用 AGH 命令执行器，在当前会话工作区执行，并跟随取消；预处理和生成共享当前工具剩余时间。自定义预设若覆盖这些期限，应保留足够的时间。

静止时连续采样可能得到完全相同的图片：每次采样的帧编号、时间和识别记录仍独立保存，导出保留全部照片；同一次工具结果只向会话模型发送一份相同图片，避免重复图片引用导致会话请求失败。

## 图像和物理结果边界

这是**四图参考生成主体、单图生成网格**方案。图片服务接收所选主视图和其余三张参考图，保持主视图；不会把四张图宣称为几何重建。接口没有保证透明输出：程序会检查实际 alpha，必要时去除与边缘相连的近白背景，无法确认透明主体则停止。白色物体、复杂背景和生成细节仍需看预览复核，AIGC 不用于识别结果、测距或夹取验证。

没有真实尺度保证；展示高度只是为了适合 Blender 预览。自动复核报告保留原始判断，导出成功不代表外形准确。实际绕物拍摄仍依赖小车运动标定、地面观察、固定目标和清空路段。收费请求失败不自动重试；需要检查配置或服务状态后再明确重做。
